routes, subject model or SPF logic. Nothing below is implemented yet.

## 3. New files to create

### `src/lib/backendMode.ts`
Reads `import.meta.env` once and exposes a typed config:

```ts
export type BackendMode = "python" | "lovable" | "mock";
export const backendConfig = {
  mode: (import.meta.env.VITE_BACKEND_MODE ?? "lovable") as BackendMode,
  pythonBaseUrl: import.meta.env.VITE_PYTHON_API_BASE_URL ?? "http://localhost:8001",
  useMockAi: import.meta.env.VITE_USE_MOCK_AI === "true",
  lovableFallbackEnabled: import.meta.env.VITE_ENABLE_LOVABLE_AI_FALLBACK === "true",
};
```
Rules: read config only through this module; never scatter `import.meta.env` across components.
Default mode when unset must be the **current** behaviour (`lovable`) so nothing breaks.

### `src/lib/pythonApiTypes.ts`
Exact TypeScript mirrors of `docs/FRONTEND_DATA_MODEL.md`. No logic, no imports from components.

### `src/lib/pythonApiClient.ts`
One thin `fetch` wrapper:
- base URL from `backendConfig.pythonBaseUrl`;
- `AbortController` timeouts per endpoint class (3 s health → 300 s import);
- parses the `APIError` envelope into a typed `PythonApiError { code, message, retryable, status }`;
- typed helpers: `getHealth`, `getModelStatus`, `getSubjects`, `getSubject`, `getLearningGoals`,
  `getMaterials`, `postChat`, `generateQuiz`, `generateMockExam`, `generateStudyPlan`, `gradeAnswer`,
  `postFeedback`, `importDocument`;
- no React imports — usable from both components and (future) server routes.

### `src/lib/pythonChatAdapter.ts`
Implements the AI SDK transport interface so `StudyChat` keeps using `useChat` unchanged:
- non-streaming first: `POST /api/chat` with `stream: false`, wrap the answer as a single UI text part;
- streaming later: consume SSE `token` / `done` events;
- attaches subject context (`subject_id`, `component_subject_id`, `language`, `academic_year`,
  `grade_level`) from `AcademicYearProvider` + route params;
- exposes the final `sources`, `exam_tip` and `used_model` so `SourceSnippetList` can render them;
- three implementations behind one factory: `python`, `mock`, `lovable` (existing
  `DefaultChatTransport({ api: "/api/chat" })`).

### `src/components/app/BackendStatusBanner.tsx`
- `useQuery({ queryKey: ["backend-health"], queryFn: getHealth, refetchInterval: 60_000, retry: false })`.
- Hidden while healthy or during the first check. Amber bar when unreachable/degraded, with Retry.
- Copy: "Study AI backend offline — grades, planner and materials still work."
- Exposes a small hook (`useBackendOnline()`) so AI buttons can disable themselves with a tooltip.
- Uses design tokens only (`--warning` for the amber state).

### `src/components/app/SourceSnippetList.tsx`
- Props: `{ sources: SourceSnippet[]; compact?: boolean }`.
- Collapsed "Sources (3)" disclosure; each row shows material name, section, page, score, snippet;
  links open `url` when present.
- Renders nothing when `sources` is empty; must never break an answer if the shape is unexpected.

## 4. Backend mode configuration

| `VITE_BACKEND_MODE` | Chat transport | Other AI features | Use case |
| --- | --- | --- | --- |
| `python` | `pythonChatAdapter` | Python endpoints | Target local setup |
| `lovable` | existing `/api/chat` | disabled/hidden | Today's behaviour, default |
| `mock` | canned responses | canned responses | UI work with no backend |

`VITE_USE_MOCK_AI=true` forces mock regardless of mode.
`VITE_ENABLE_LOVABLE_AI_FALLBACK=true` allows falling back to `/api/chat` when Python is
unreachable — **off by default**, and fallback answers must be visibly labelled "Cloud fallback".

## 5. `.env.local`

Create `.env.local` (gitignored, never committed):

```env
VITE_PYTHON_API_BASE_URL=http://localhost:8001
VITE_BACKEND_MODE=python
VITE_USE_MOCK_AI=false
VITE_ENABLE_LOVABLE_AI_FALLBACK=false
```

## 6. Mock mode

- Fixtures under `src/lib/mock/ai-fixtures.ts`: one chat answer per language, two source snippets,
  a 5-question quiz, a 3-question exam, a grading result, a 4-item study plan.
- Simulated latency (~600 ms) so loading states are exercised.
- Every mock output is visibly tagged "Mock mode" — never presented as a real AI answer.
- Mock mode ties into the existing `DemoMode` toggle so the prototype demo stays coherent.

## 7. Backend-unavailable mode

- Health check on app start and every 60 s while an AI screen is open.
- Non-AI screens (`/school`, `/stats`, `/planner`, `/profile`, `/settings`, `/help`) must stay
  fully functional — they only read `localStorage`.
- AI actions become disabled with an explanatory tooltip; no blocking modals.
- Failed feedback is queued locally and retried when health recovers.

## 8. Preserving the existing chat UI

Unchanged: sidebar layout, thread dialog, `Conversation`/`Message`/`PromptInput`/`Shimmer`,
markdown rendering, the "Ready to study?" empty state, toast error handling, `chat.status`
loading semantics. Only the transport and the extra sources/exam-tip block are new.

## 9. Displaying RAG sources and model status

- Sources: `SourceSnippetList` directly under each assistant message, collapsed by default.
- Exam tip: subtle bordered callout below the answer, above sources.
- Model status: `provider · model · mode · latency` row in `/settings` and `/diagnostics`;
  optional compact chip in the chat header showing `used_model` from the last answer.

## 10. Auth handling in Stage 1

- Supabase auth stays exactly as-is; the `_authenticated` gate is untouched.
- The local Python backend does not verify Supabase JWTs in Stage 1. Send a non-sensitive
  `X-Student-Id` header (Supabase user id) for per-student data partitioning, and bind uvicorn to
  `127.0.0.1` so it is not reachable off-device.
- If the backend is ever exposed beyond localhost, add real token verification **before** doing so.

## 11. Secrets policy

- Everything in `VITE_*` is inlined into the browser bundle — treat it as public.
- Allowed in `VITE_*`: the Python base URL, backend mode flags, the Supabase publishable/anon key.
- **Never** in `VITE_*`: Supabase service-role key, `LOVABLE_API_KEY`, OpenAI/Anthropic/HF keys,
  remote GPU tokens, database passwords.
- Model-provider credentials live only in the Python backend's own `.env`, server-side.
- If a remote model endpoint needs a token, the browser must never hold it: the browser calls
  FastAPI, and FastAPI calls the provider.

## 12. Lovable AI Gateway as optional fallback

Keep `src/lib/ai-gateway.server.ts` and `src/routes/api/chat.ts` compiling and working. They are
only reachable when `VITE_BACKEND_MODE=lovable` or `VITE_ENABLE_LOVABLE_AI_FALLBACK=true`.
Remove them only after Python chat is confirmed working and the user explicitly asks.

## 13. Suggested implementation order

1. `backendMode.ts` + `pythonApiTypes.ts` + `pythonApiClient.ts` (no UI change).
2. `BackendStatusBanner` in `AppShell` + health row in `/diagnostics` — proves connectivity.
3. `pythonChatAdapter` non-streaming, behind `VITE_BACKEND_MODE=python`.
4. `SourceSnippetList` + exam tip.
5. Learning goals + backend materials in the subject dashboard.
6. Quiz → mock exam → grader → study plan.
7. Feedback endpoint.
8. Streaming (SSE) upgrade.
9. Only then revisit thread persistence and any Supabase/Gateway removal.
